# Token Maxx

A small personal iOS app plus a set of widgets that show how much of your AI coding-tool
quotas you've used and when each one resets:

| Service  | What's shown |
|----------|--------------|
| **Cursor**   | Included-usage % for Auto models, other (API) models, and the total; on-demand spend |
| **Grok Bot** | Weekly usage % (same Cursor login) |
| **Codex**    | ChatGPT/Codex 5-hour and weekly rate-limit windows, credits |
| **Claude**   | 5-hour, weekly (all models), weekly Opus / Sonnet utilization, extra usage |

> ⚠️ **Unofficial and fragile.** Every endpoint below is a private or undocumented API
> that the vendors use for their own dashboards and CLIs. They can change or disappear at any
> time, and using them may be against a service's terms. This is a personal TestFlight-only
> tool; it isn't affiliated with Cursor, xAI, OpenAI or Anthropic.

There's no backend. Credentials are stored **only** in the iOS Keychain (shared access group
`XPU32D9V4J.com.AnomalousResearch.UsageLimits.shared`, `kSecAttrAccessibleAfterFirstUnlock`)
so the widget extension can read them after the first unlock. The last-known snapshots are
cached as JSON in the app group `group.com.AnomalousResearch.UsageLimits`.


## Building

Requirements: Xcode 27 (iOS 18 SDK or newer), [XcodeGen](https://github.com/yonaskolb/XcodeGen).

```sh
brew install xcodegen
xcodegen generate
open UsageLimits.xcodeproj         # or build from the command line:

xcodebuild -project UsageLimits.xcodeproj -scheme UsageLimits \
  -destination 'generic/platform=iOS' -configuration Release \
  -archivePath build/UsageLimits.xcarchive archive

xcodebuild -exportArchive -archivePath build/UsageLimits.xcarchive \
  -exportPath build/export -exportOptionsPlist ExportOptions.plist   # method: app-store-connect
```

Signing is Automatic with team `XPU32D9V4J`. The App ID and widget App ID need the
**App Groups** capability with `group.com.AnomalousResearch.UsageLimits`; Xcode's automatic
signing creates this for you. Swift language mode is 5 (`SWIFT_VERSION = 5.0`), deployment
target iOS 18.0.

## Endpoints used

### Cursor + Grok Bot (one login)

The credential is the `WorkosCursorSessionToken` cookie, `"<userId>%3A%3A<JWT>"`. The Bearer
token is the part after `%3A%3A` (URL-encoded `::`).

* **Grok Bot** – `POST https://api2.cursor.sh/aiserver.v1.DashboardService/GetSandUsageStatus`
  with `Authorization: Bearer <JWT>`, body `{}`. Uses `usagePercent`, `nextResetTimestampUtc`,
  `currentPeriodStart`, `grokPlanLabel`, `cursorPlanName`, `onDemandSettings.enabled`,
  `hasAvailableUsage`. Shown as one "Weekly" window.
* **Cursor** – `GET https://cursor.com/api/usage-summary` with
  `Cookie: WorkosCursorSessionToken=<value>`, `Origin`/`Referer` set to cursor.com. Uses
  `billingCycleStart/End`, `membershipType`, `individualUsage.plan.{autoPercentUsed,
  apiPercentUsed, totalPercentUsed, used, limit}` (cents) and `individualUsage.onDemand`.
  If the plan block is missing, falls back to
  `POST https://api2.cursor.sh/aiserver.v1.DashboardService/GetCurrentPeriodUsage`
  (`planUsage`, `spendLimitUsage`, and the `*DisplayMessage` strings, parsed for `NN%`).
* **The X Subscription (unified accounts)** – Grok, Grok Bot and Cursor share one weekly pool
  (Grok models only). Detected when `GetSandUsageStatus` succeeds and usage-summary has no
  `individualUsage.plan` percentages, or when `membershipType` / `cursorPlanName` /
  `grokPlanLabel` / `subscription` / `planName` names the X Subscription. Grok Bot's window
  is then labelled "Shared weekly" and Cursor mirrors it (`cursor.shared`) instead of the
  billing-cycle pools. Third-party model spend (billed at API rates) comes from
  `POST https://cursor.com/api/dashboard/get-aggregated-usage-events` (same cookie headers,
  body `{"teamId":-1,"startDate":"<ms>","endDate":"<ms>"}`) as the sum of `totalCents` over
  `aggregations` whose `modelIntent` isn't grok/composer/auto/default/cursor, from
  `billingCycleStart` (or `currentPeriodStart`) to now. Omitted when unavailable. These
  endpoints are untested against a live unified account.

### Codex (ChatGPT)

* `GET https://chatgpt.com/backend-api/wham/usage` with `Authorization: Bearer <accessToken>`
  and `ChatGPT-Account-Id` when known. Uses `plan_type`,
  `rate_limit.primary_window` / `secondary_window` (`used_percent`, `limit_window_seconds`,
  `reset_at` unix seconds — either window may be null), `credits`, and
  `rate_limit_reset_credits.available_count`.
* Access tokens come from `GET https://chatgpt.com/api/auth/session`. On a 401 the app
  re-calls that endpoint with the stored `__Secure-next-auth.session-token` cookie to mint a
  fresh token; if that fails you'll see "Session expired — sign in again".

### Claude

* OAuth 2 + PKCE as the Claude Code public client (`9d1c250a-e61b-44d9-88ed-5944d1962f5e`):
  authorize at `https://claude.ai/oauth/authorize`, redirect
  `https://console.anthropic.com/oauth/code/callback`, scopes
  `org:create_api_key user:profile user:inference`.
* Tokens: `POST https://console.anthropic.com/v1/oauth/token` (`authorization_code` and
  `refresh_token` grants). The app refreshes automatically when the token is about to expire.
* Usage: `GET https://api.anthropic.com/api/oauth/usage` with `anthropic-beta: oauth-2025-04-20`.
  Uses `five_hour`, `seven_day`, `seven_day_opus`, `seven_day_sonnet` (`utilization`, and
  `resets_at` as ISO-8601 or unix seconds) and `extra_usage`.
* After an HTTP 429 the app honours `Retry-After` and won't call the endpoint again until then,
  from either the app or the widget.

## Signing in

Each service's sheet (tap a card's `…` button or **Sign In**) has an automatic flow and a
**Paste token manually** fallback.

* **Cursor / Grok Bot** – an in-app web view opens `cursor.com/dashboard`. Once you're logged in
  the `WorkosCursorSessionToken` cookie is captured. Manual: copy that cookie from desktop
  DevTools (Application → Cookies). A bare JWT also works; the user id is read from its `sub`.
  Note that Google sign-in often refuses embedded web views, so use email or GitHub login
  (or paste the cookie).
* **Codex** – an in-app web view opens `chatgpt.com`. After login the app calls
  `/api/auth/session` from inside the page and stores the access token, account id and session
  cookie. Manual: paste `accessToken` from `chatgpt.com/api/auth/session` (account id and session
  cookie are optional; the cookie makes automatic refresh possible).
* **Claude** – either
  1. **In-app**: a web view runs the authorize URL and catches the redirect to the callback page,
     reading `code` and `state` automatically; or
  2. **System browser**: opens the authorize URL in an `ASWebAuthenticationSession`. Copy the
     `code#state` shown on the callback page, tap Cancel, and paste it into the sheet.

  Manual: paste an OAuth access token, plus a refresh token if you have one (a refresh token on
  its own also works).

**Sign Out** deletes that service's Keychain items, its cached snapshot, and the web view's
cookies for that domain. Cursor and Grok Bot sign out together.

## Widgets

One configurable widget (App Intent) supporting:

* **Small** – a ring gauge for one window, plus the reset countdown
* **Medium** – the 3 most constrained windows (or the chosen service's windows) as bars
* **Large** – all services summarized
* **Lock Screen circular** – capacity gauge
* **Lock Screen rectangular** – name, linear gauge, "resets in …"
* **Lock Screen inline** – e.g. `Codex 100% · 2d`

Configure **Service** (a specific one, or *Most constrained*) and **Window** (*Most
constrained*, *Shortest*, *Longest*). The timeline provider tries a live fetch using the shared
Keychain and falls back to the cached snapshots, then reloads after 20 minutes. The app also asks
WidgetKit to reload whenever it refreshes.
